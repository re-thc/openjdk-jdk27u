# Bounds and dispatch audit

The follow-on changes retain the existing interpreter/C1/C2 calling conventions, publication ordering, native windows and tier policies. The checked equality wrapper remains C1-only; C2 reaches the existing JDK equality intrinsic through its Java null checks. The vendor/kernel sources and tracked overlap/bit-operation patches are unchanged.

For the four-code-unit UTF-16 probe, `StringUTF16.lastIndexOf` checks the physical source and target array ends before calling the verifier. Public normalization supplies a nonnegative candidate start. One unaligned eight-byte equality therefore covers exactly the four code units, with no prefix or additional range-helper call. Both byte arrays use the same encoding, so the equality is independent of native byte order. Builder searches remain bounded by the normalized logical length.

The shared verifier keeps its required source/target checks. Its fast guards are equivalent to the preceding range checks; invalid ranges still call the original JDK checks in source-then-target order. Valid calls avoid cold helper calls. After the suffix matches, prefixes through sixteen bytes use at most two word comparisons. If the prefix has length P and the checked suffix has at least eight bytes, the final word ends no later than P+7, which lies inside the checked complete needle. Overlapping suffix bytes have already matched, so they cannot invent a prefix mismatch. Native byte order selects leading/trailing zero counts to return the same first mismatching prefix-byte index. Larger prefixes retain `ArraysSupport.mismatch`.

The existing public-search suffix tests now include widths 12/13,15/16/17,24/25 and31/32/33 in addition to longer controls. They exercise both coders, high- and low-byte differences, every suffix position through seventeen, single/two-candidate windows, misses and overlapping matches. Physical-array bounds, logical builder lengths, JNI, header layouts, tiers and work/safepoint tests remain separate checks.

MSVC selects the repository's per-file HIGHEST optimization only for `StringZillaKernels.c`. The repository optimization macros yield /O2 for release and fastdebug and /Od for slowdebug. GCC optimization settings are unchanged. The native workflow separately checks actual generated MSVC commands and recompiles the native fixture under /O2; macro checks alone do not qualify that production image.

Invalid public integer code points retain their Java miss behavior. JNI transitions resolve handles before deriving array addresses, and the bounded pure native body performs no safepointing work after that point.
