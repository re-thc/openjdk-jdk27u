Timing uses JMH 1.37, one thread, fresh JVM per observation, a 256 MiB heap,
SerialGC, USE_SPEC=true and SCOPE_DEDUP_DEPTH=2. Main: five A/B rounds,
alternating AB/BA and reversing case order each round; 3 x 400 ms warmup and
3 x 400 ms measurement. Controls use three rounds. Longer checks use five
rounds with 3 x 1 s warmup and 3 x 1 s measurement. Reported values are the
median of each fork's three measurement iterations, then the median across
forks. Brackets are minimum/maximum fork medians, in ns/call. Negative time
change is faster. CSV also retains quartiles and paired relative changes.
Completed 374 fresh timed JVM forks across 49 case/protocol combinations.
No builds, correctness tests or other benchmark suites overlapped timings.
CPU affinity, frequency and background OS activity were not fixed. Thermal
status could not be read through the session sandbox; no thermal claim is made.

Each call invokes the exact same exported, noinline shared_arena_five function:
1000 plus the five pointed-to int64 values (a data NULL contributes zero).
JNI takes the same dynamic function address and performs an indirect call.
The JNI control uses --add-exports to call the same internal
MemorySessionImpl.acquire0/release0 operations as FFM.
Both paths validate the symbol first, then each pointer in order, acquire
arenas before passing addresses to native code, hold them across the call,
and release successful acquisitions in finally. Setup checks both results;
allocation, library lookup, native resolution and arena creation/close are
outside timing. No arena is pre-acquired and no address is precomputed for
the JNI timing path. JNI uses fixed local ownership slots, no per-call arrays
or allocation, and deduplicates against every held session. FFM intentionally
retains its bounded argument-slot cache plus the most recent uncached session.
'checkedJNI' means these Java lifetime/native-address checks. VM -Xcheck:jni
is measured separately below, with identical VM flags for both competitors.

Letters identify arenas, not values. AAAAA repeats one pointer. AABBB puts
arena B beyond the first two fixed argument slots, both occupied by A.
AABAB hits fixed A between B uses; ABCBC hits fixed B between C uses.
AABCB evicts uncached B with C before reusing B. ABCDE has five distinct
arenas. S in SABBB shares the symbol's arena. 'slices' uses different offsets
in A,A,B,B,B, proving session identity rather than address identity is reused.

and all-distinct shared cases remain approximately flat. Main checked-JNI
A/B medians vary by at most about 2.4%, with the largest scatter in AABCB;
the JNI implementation is identical in A/B.

AABCB remains a bounded-cache limitation: FFM acquires B twice, while JNI's
full deduplication acquires it once. This costs roughly 4 ns beyond checked
JNI on this host. Its extra cache miss also introduces a small A/B regression.
The distinct-confined case pays extra comparisons without shared-session
atomic operations to save. These are measured regressions with small absolute
costs. Eliminating all such misses would require a broader cache/search
policy with different costs for wide calls.
The large demonstrated repeated-arena overhead is fixed by the existing
single local, which keeps validation and release ownership intact.
The reported small costs are the bounded cache tradeoff.

Compile SharedArenaCall.java with JMH 1.37 and annotation processing, adding
--add-exports=java.base/jdk.internal.foreign=ALL-UNNAMED. Compile libSharedArenaCall.c
as a shared library with JDK JNI include directories and test/lib/native/export.h.
Place classes under bench/classes, JMH jars under deps, library under bench/native.
The driver expects A at baseline-src/build/ffm-baseline/jdk and B at build/ffm-candidate/jdk.
Run python3 build/ffm-20261030/run_ab.py --suite main for the main series;
--suite controls/existing/gc/jniinline/jnicheck --rounds 3 reproduces each
follow-up. Long checks use --suite long --patterns AABCB --rounds 5 and
--suite long --lifetime confined --patterns ABCDE --rounds 5.
JMH uses a local socket for forks, so run outside a socket-blocking sandbox.
