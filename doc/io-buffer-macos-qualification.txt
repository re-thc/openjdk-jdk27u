Decision
Retain the shared opportunistic staging implementation. No sustained runtime
regression against A was demonstrated in quota-exhausted, mixed-quota, tiny
socket, or arbitrary-channel controls. Native staging saves heap allocation
and improves the measured cache-hot loopback socket-to-file path. Compiler
code growth and adverse pairs remain visible below; this is not proof that
every workload or cold invocation is faster.
Fix the demonstrated macOS correctness bug: count=0 must not reach sendfile,
where zero requests transmission through EOF. The included TransferSocketChannel
test fails with "zero count" on both A and original B and passes on final B.
The fix is confined to macOS FileDispatcherImpl.c; shared staging is unchanged.
The shared handback retains the known baseline TransferSocketChannel failure
until the independent fix is applied; the 44-pass result is for their combination.

Measurement protocol
Local Java harness, standard library plus existing JavaNioAccess for mixed quota;
Python runner/analyzer use only the standard library. No framework added.
One scenario per fresh JVM. Eight adjacent A/B pairs per scenario, alternating
AB and BA; rotate scenarios each round and reverse odd rounds. Run serially,
with no build/test activity during timed series. No timed sample was discarded.
Fixed JVM settings: -Xms256m -Xmx256m -Xshare:off -XX:MaxDirectMemorySize=1m,
virtual scheduler parallelism 2. Five warmup batches and at least one second
of warmup, then five equal-operation samples. A fork contributes its sample
median; A and B columns are medians of eight fork medians. Paired percent is
median(B_i/A_i - 1), which need not equal the ratio of the displayed A/B medians.
95% intervals use 10,000 paired bootstrap resamples, seed 20261030; they are
descriptive small-sample intervals, with no multiple-comparison adjustment.
CPU is process CPU ns/op, including sender, GC and any concurrent compilation;
it can exceed wall time and is sensitive to sender scheduling. Allocation is
ThreadMXBean total allocated heap bytes; setup, formatting and verification are
outside samples. Caller allocation is also in CSV; virtual caller values are -1
because that per-thread counter does not support virtual threads. Native malloc
traffic is not counted as heap allocation: eligible calls allocate/free min(count,
8192) native bytes, rounded to address size, with a reservation of that capacity.
Available native calls perform three reservation and three release atomics;
failed quota probes perform no successful reservation or cleanup/retry loop.
FileChannel and socket setup are excluded. The sender continuously writes 64 KiB
heap batches over loopback; transferFrom overwrites position zero of the same
temporary file. Verify exact count, unchanged file position and every final byte.
No fsync: these are page-cache writes, not durable storage or production network tests.
Per sample: socket/arbitrary ops=max(300,min(60000,64 MiB/size)); empty=100000.
Exhausted holds a live 1 MiB direct buffer for the entire fork. Mixed alternates
a full-budget reservation and a free budget on each transfer, charging the same
reservation/release operations to A and B. Existing temporary I/O caches are unmetered.
Empty is a nonblocking socket with no incoming data; arbitrary is a custom heap source.

C2 and inlining overhead
Separate PrintInlining/LogCompilation runs show the staging method grows from
137 to 322 bytecodes, three below aarch64 FreqInlineSize=325. Bits.tryReserveMemory
grows from 52 to 75 after moving limit initialization. Both the staging method
and the 6-byte access wrapper / 75-byte reservation method hot-inline in the
observed available, denied and arbitrary controls. Mixed heap/direct type profiles
can compile both paths and recompile; some compilations reject calls as already
compiled into a big method. This is compiler overhead, not an unconditional lost inline.
One diagnostic mixed-8-KiB pair illustrates the cost: transferFrom C2 nmethod content was
1,912 bytes / 3 ms task duration for A, versus 50,912 / 99 ms for B; standalone
staging was 11,152 / 8 ms versus 27,064 / 50 ms. Native-only tiny transferFrom
instead shrank 17,152 -> 13,016 content bytes. These are single diagnostic task observations,
not paired estimates of compiler CPU or a general code-size ratio. Logging, profiles
and compiler scheduling affect them. The steady-state process CPU table is the
measured CPU cost; cold-start and uncommon caller compilation remain uncertain.
